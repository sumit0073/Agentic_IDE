Product Architecture

Desktop-first. Code stays on the customer machine.

Three core architectural principles govern Ledger — not a generic marketing checklist.

01 / AUDIT

Local agent runtime

Every READ, EDIT, RUN, and APPROVAL is executed on your local machine and logged into an auditable ledger — never a remote black box.

02 / CONTROL

Permissions before execution

Suggest, Approve, or Controlled Auto-run. Destructive edits and shell tools running through node-pty stop for your explicit sign-off.

03 / PRIVACY

Code never leaves your box

The cloud control plane handles only identity via Clerk, quotas via Redis, and billing via Stripe. Your source tree is never mirrored or stored remotely.

Security & Architecture

Answers for engineers who care about their code.

No mystery hand-waving. Here is exactly how Ledger handles code privacy, model routing, checkpoints, and permissions.

Does my codebase get uploaded to the cloud? +
No. Ledger is desktop-first: all source files, git commits, and terminal executions remain 100% on your local machine. The cloud control plane strictly isolates identity (Clerk), usage quotas (Redis), and billing (Stripe). Only the minimal semantic snippet chunks needed for inference pass through the model gateway.
What is the locked technology stack behind Ledger? +
TypeScript is used everywhere. The customer client is built with Electron, React, Monaco editor (MVP → Code-OSS roadmap), and xterm.js + node-pty for native terminal sessions. The cloud control plane runs a Node API (Fastify / Nest), PostgreSQL, Redis quotas, Clerk authentication, and a Next.js admin console.
How does the 1-Click Checkpoint Rollback work? +
Before an agent task begins executing, Ledger automatically creates a lightweight local checkpoint of all files slated for modification. If the agent makes an erroneous edit or breaks tests, clicking Roll back this task instantly restores your workspace to its exact prior state.
Where are AI model API keys stored? +
Provider keys (Anthropic, OpenAI, Google) stay strictly server-side inside the secure Model Gateway. The desktop client authenticates using a signed Clerk session token, so raw API keys are never exposed on client machines or bundled in app code.
How does Controlled Auto-run prevent dangerous bash commands? +
Controlled Auto-run permits low-risk operations (such as reading source files, running formatting, or running test runners on an approved allowlist) without interruption. However, privileged actions (such as deleting files, running package install scripts, or invoking external network APIs) strictly halt execution for engineer approval.
Can Clerk auth be swapped for enterprise Okta or Auth0? +
Yes. Clerk is our turnkey identity solution for v1. The Node API control plane is engineered with a modular auth interface, allowing seamless drop-in integration with Auth0, Okta, or custom SAML providers for enterprise deployments.
